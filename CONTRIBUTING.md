# Contributing to RebornForge

RebornForge welcomes sourced documentation, corrections, product proposals, and accessibility feedback. Application development has not been authorized.

## Before contributing

Read the [governance](GOVERNANCE.md), [code of conduct](CODE_OF_CONDUCT.md), and [rights guidance](docs/RIGHTS_AND_PRESERVATION.md). Discuss substantial changes through an issue before implementing them. An issue, consensus, or silence is not founder approval.

Do not submit confidential information, credentials, unauthorized software archives, or protected material without permission. Use [security guidance](SECURITY.md) for vulnerabilities.

## Workflow

1. Identify the approved scope and relevant decision, or submit a proposal.
2. Work on a dedicated branch or fork for one coherent change. Never push directly to main.
3. Write public content in international English; credit sources and distinguish facts from assumptions.
4. Open a pull request describing the purpose, files, verification, results, impact, and risks. Use a draft for unresolved decisions.
5. Address feedback and report only checks actually performed.
6. Wait for explicit founder authorization. Do not merge automatically or deploy.

The founder alone decides whether a proposal becomes project policy. Contributors and AI agents cannot change architecture, licenses, sensitive permissions, costs, or publication plans without approval.

## Verification

For documentation, check links, Markdown rendering, factual claims, document consistency, and template syntax. Do not claim automated checks ran when they did not.

Future UI pull requests must include actual screenshots where tools permit, approved mockup references, desktop/mobile verification, accessibility checks, and disclosure of significant visual deviations.

## Rights and licensing

No repository license has been selected yet. Do not assume contribution or publication transfers copyright or establishes a license. Broad external contributions should wait until contribution and licensing terms are approved. Proposals and corrections can still be discussed without uploading protected content.
