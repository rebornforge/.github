## Français

# Profils et parcours hypothétiques

Aucun entretien, test ou chiffre d’usage n’a été recueilli. Ces profils servent au cadrage ; la phase 2 devra les confronter à des observations.

| Profil | Besoin | Difficulté à vérifier |
| --- | --- | --- |
| Ancien utilisateur curieux | Retrouver un nom et comprendre ce qui est devenu le projet | Souvenirs imprécis, liens morts, confusion original/fork |
| Documentaliste bénévole | Ajouter des faits et sources avec attribution | Droits inconnus, doublons, effort de saisie |
| Développeur de renaissance | Vérifier si une reprise légitime existe et proposer la sienne | Faux sentiment d’autorisation, initiatives concurrentes |
| Créateur ou ayant droit | Faire corriger une attribution ou demander un retrait | Exposition de preuves privées dans les issues |
| Fondateur/modérateur | Publier des informations fiables sans être submergé | Charge, conflits d’intérêts et décisions non tracées |

## J1 — Découvrir

Accueil → catalogue → recherche/filtre → fiche historique → sources ou initiative liée. Sans connexion. Si aucun résultat : retirer les filtres ou proposer un projet. Si une source est morte : mentionner son état, sans inventer de remplacement.

## J2 — Documenter

Consulter les règles → connexion → vérifier les doublons suggérés → remplir proposition et références → confirmation avec identifiant → suivi privé. Un refus ou une demande de précisions explique le motif. Un échec de connexion ne doit pas publier ni perdre silencieusement une soumission.

## J3 — Corriger ou proposer une renaissance

Depuis une fiche → correction ou initiative → faits, sources, relation et droits → revue → publication liée à l’historique. L’absence d’autorisation de réutilisation n’empêche pas une correction historique ; elle interdit de présenter la reprise comme autorisée.

## J4 — Examiner

Modérateur autorisé → file → comparaison avant/après et sources → demander précisions, rejeter ou publier avec motif. Deux revues concurrentes doivent signaler une version périmée. Toute modification postérieure repasse en revue.

## J5 — Signaler

Fiche → signaler/corriger → modèle d’issue et rappel public → URL, résumé non sensible et action demandée → traitement humain. Sans compte GitHub, lecture des consignes possible mais création d’issue indisponible : limite à expliquer, pas de faux formulaire fonctionnel.

## Questions pour la phase UX

Tester la compréhension des statuts séparés, l’effort du formulaire, les besoins des personnes sans GitHub, le changement de langue et la distinction entre sources, archives et fichiers redistribués. Aucun choix visuel n’est arrêté.

## English

# Hypothetical users and journeys

No interviews, usability tests or usage figures have been collected. These profiles frame the product; phase 2 must test them against observations.

| User | Need | Barrier to validate |
| --- | --- | --- |
| Curious former user | Rediscover a name and understand what happened | Unclear memories, dead links, original/fork confusion |
| Volunteer documentalist | Add sourced facts with attribution | Unknown rights, duplicates, data-entry burden |
| Revival developer | Find legitimate continuations and propose their own | Assumed permissions and competing initiatives |
| Creator or rights holder | Correct attribution or request removal | Private evidence exposed in issues |
| Founder/moderator | Publish reliable information within available capacity | Workload, conflicts and unrecorded decisions |

## J1 — Discover

Home → catalogue → search/filter → historical record → sources or linked revival. No sign-in. With no results, reset filters or propose a project. Identify dead sources without inventing replacements.

## J2 — Document

Read rules → sign in → check suggested duplicates → enter proposal and sources → reference-number confirmation → private tracking. Rejection or clarification requests explain why. Sign-in failure must neither publish nor silently lose a submission.

## J3 — Correct or propose a revival

Record → correction or initiative → facts, sources, relationship and rights → review → publication linked to history. Missing reuse permission does not prevent historical corrections; it prevents presenting a revival as authorized.

## J4 — Review

Authorized moderator → queue → before/after comparison and sources → request clarification, reject or publish with a reason. Concurrent reviews must detect stale versions. Later changes require a fresh review.

## J5 — Report

Record → report/correct → issue template with public-visibility notice → URL, non-sensitive summary and requested action → human handling. People without GitHub can read instructions but cannot create an issue: disclose this limitation instead of presenting a fake working form.

## UX research questions

Test understanding of separate statuses, submission effort, needs of people without GitHub, language switching and the difference between sources, archives and redistributed files. No visual design is selected.
