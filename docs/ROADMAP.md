# Operational roadmap

Every phase requires explicit founder approval before the next begins. Dates and MVP scope remain uncommitted.

| Phase | Deliverable | Exit gate |
| --- | --- | --- |
| 0 — GitHub Foundation | Audit, foundation documents, templates, proposed protections, first PRs | Founder accepts documents and separately authorizes settings |
| 1 — Product Definition | MVP scope, exclusions, personas, user stories, acceptance criteria, priorities | Product scope approved |
| 2 — UX Research | Comparison of GitHub, GitLab, Product Hunt, AlternativeTo, Software Heritage and preservation communities; journeys and navigation | UX findings approved |
| 3 — UI Concepts | Consultable homepage mockups for Digital Forge, Digital Heritage and Modern Community; tradeoffs and recommendation | Visual direction selected |
| 4 — Detailed Mockups | Main MVP pages, desktop/mobile layouts, interactive, empty, loading and error states | Pages approved before prototyping |
| 5 — Interactive Prototype | Approved prototype technology, navigable demonstration, clearly identified fictional data and simulated behavior | Founder tests and explicitly approves prototype |
| 6 — Design System | Tokens, components, responsive rules, accessibility guidance | Design system approved |
| 7 — Technical Architecture | Compared options, data model, API, authentication, internationalization, Docker and test strategy | Architecture approved |
| 8 — Application Development | Only features in the approved MVP | Acceptance criteria implemented |
| 9 — Quality Assurance | Functional, integration, security, accessibility, responsive and visual checks; fixes | Candidate accepted |
| 10 — Release | Installation documentation, deployment preparation, backups, restoration and final checks | Explicit production authorization |

## Current authorization

Only phase 0 documentation preparation is approved. No application development, prototype technology, new repository, security-setting change, deployment, or merge is authorized by that approval.

Keep foundation documentation in this repository for now. Separate docs and community repositories are proposals to defer, not approved creation plans. Architecture, licenses, design direction, moderation scope, and MVP remain open.

## Proposed next step

After the foundation PR is reviewed and merged by the founder, propose a bounded phase 1 product-definition package. Do not start it implicitly.
