## Français

# Feuille de route opérationnelle

Chaque phase requiert la validation explicite du fondateur avant la suivante. Les dates et le MVP ne sont pas arrêtés.

| Phase | Livrable | Validation |
| --- | --- | --- |
| 0 — Fondations GitHub | Audit, documents, modèles, protections proposées, premières PR | Documents acceptés ; réglages autorisés séparément |
| 1 — Définition produit | MVP, exclusions, profils, user stories, critères, priorités | Périmètre approuvé |
| 2 — Recherche UX | GitHub, GitLab, Product Hunt, AlternativeTo, Software Heritage et préservation ; parcours et navigation | Conclusions approuvées |
| 3 — Concepts UI | Maquettes d’accueil consultables Digital Forge, Digital Heritage et Modern Community ; comparaison | Direction choisie |
| 4 — Maquettes détaillées | Pages MVP desktop/mobile ; états interactifs, vides, chargement et erreurs | Pages validées avant prototype |
| 5 — Prototype interactif | Technologie approuvée, démonstration navigable, données fictives et simulations explicites | Prototype testé et validé |
| 6 — Design system | Tokens, composants, responsive, accessibilité | Design system approuvé |
| 7 — Architecture | Comparaison, données, API, authentification, internationalisation, Docker, tests | Architecture approuvée |
| 8 — Développement | Uniquement le MVP approuvé | Critères réalisés |
| 9 — Qualité | Tests fonctionnels, intégration, sécurité, accessibilité, responsive, fidélité visuelle | Version candidate acceptée |
| 10 — Livraison | Installation, déploiement préparé, sauvegardes, restauration, contrôles finaux | Production explicitement autorisée |

## Autorisation actuelle

La préparation documentaire de phase 0 et le cadrage produit de phase 1 sont autorisés, avec français prioritaire et traduction anglaise. Le [MVP proposé](product/README.md) attend validation. Aucun développement, technologie de prototype, nouveau dépôt, réglage de sécurité, déploiement ou fusion n’est implicitement approuvé.

Conservez les fondations dans ce dépôt. Reporter les dépôts documentation et communauté reste une proposition. Architecture, licences, design, modération et MVP restent ouverts.

La future internationalisation doit privilégier le français et fournir l’anglais, avec possibilité d’ajouter d’autres langues.

## Suite proposée

Examiner le dossier de phase 1 et arbitrer le MVP. La phase 2 de recherche UX nécessite une nouvelle autorisation explicite.

## English

# Operational roadmap

Every phase requires explicit founder approval before the next begins. Dates and MVP scope remain uncommitted.

| Phase | Deliverable | Exit gate |
| --- | --- | --- |
| 0 — GitHub Foundation | Audit, foundation documents, templates, proposed protections, first PRs | Founder accepts documents and separately authorizes settings |
| 1 — Product Definition | MVP scope, exclusions, personas, user stories, acceptance criteria, priorities | Product scope approved |
| 2 — UX Research | Comparison of GitHub, GitLab, Product Hunt, AlternativeTo, Software Heritage and preservation communities; journeys and navigation | UX findings approved |
| 3 — UI Concepts | Consultable homepage mockups for Digital Forge, Digital Heritage and Modern Community; tradeoffs and recommendation | Visual direction selected |
| 4 — Detailed Mockups | Main MVP pages, desktop/mobile layouts, interactive, empty, loading and error states | Pages approved before prototyping |
| 5 — Interactive Prototype | Approved prototype technology, navigable demonstration, clearly identified fictional data and simulated behavior | Founder tests and explicitly approves prototype |
| 6 — Design System | Tokens, components, responsive rules, accessibility guidance | Design system approved |
| 7 — Technical Architecture | Compared options, data model, API, authentication, internationalization, Docker and test strategy | Architecture approved |
| 8 — Application Development | Only features in the approved MVP | Acceptance criteria implemented |
| 9 — Quality Assurance | Functional, integration, security, accessibility, responsive and visual checks; fixes | Candidate accepted |
| 10 — Release | Installation documentation, deployment preparation, backups, restoration and final checks | Explicit production authorization |

## Current authorization

Phase 0 documentation and phase 1 product definition are authorized. The [proposed MVP](product/README.md) awaits approval. No application development, prototype technology, new repository, security-setting change, deployment, or merge is authorized by that approval.

Keep foundation documentation in this repository for now. Separate docs and community repositories are proposals to defer, not approved creation plans. Architecture, licenses, design direction, moderation scope, and MVP remain open.

## Proposed next step

Review phase 1 and decide the MVP. Phase 2 UX research requires a new explicit authorization.
